## 2. 项目背景

客户在货物已出库或派送途中，可能因订单取消、地址错误、买家退款等原因需要**拦截货件并退回海外仓**。原流程中客服需线下联系海外仓，存在三个问题：

1. **拦截粒度不统一** —— 一个运单下有多箱，若允许按箱勾选拦截，会出现「同一运单部分箱被拦截」的中间态，海外仓无法按票执行，导致漏拦或误拦。
2. **拦截结果不可见** —— 客户提交拦截后无法得知海外仓是否拦截成功，只能反复找客服确认。
3. **异常单不醒目** —— 拦截失败意味着货物已派送出去、产生实际损失，但在指令列表中与普通指令混在一起，无法快速定位。

本 PRD 定义从**客户发起拦截**到**指令列表回传拦截结果**的完整链路，明确「整票拦截」的粒度约束，以及拦截结果在列表中的展示规范。

## 3. 产品目标

1. 客户可为运单发起拦截指令，拦截指令无需填写收件地址。
2. **拦截必须以「整票运单」为最小单位**，不支持按箱勾选，从源头消除中间态。
3. 拦截结果（成功 / 失败）由海外仓回传，客户在指令列表中可直接查看。
4. 拦截失败的单据需在列表中**整行红色高亮**，便于运营快速识别并跟进。
5. 全流程可追溯：谁在什么时间对哪票运单发起了拦截、结果如何。

## 5. 用户角色与权限

| 角色 | 核心诉求 | 主要权限 |
| --- | --- | --- |
| 客户 / 客服 | 对运单发起拦截、查看拦截是否成功 | 创建拦截指令、查看指令列表 |
| 运营 | 跟进拦截失败单据 | 查看指令列表、筛选异常单 |
| 海外仓 | 执行拦截并回传结果 | 回传拦截成功 / 拦截失败 |

## 6. 核心业务规则

### 6.1 粒度规则（关键约束）

> **拦截指令的提交粒度是「整票运单」，不是「箱子」。**

- 一个运单下所有箱子作为一个整体被拦截，不支持单独勾选部分箱子下指令。
- 依据：海外仓按运单（票）执行拦截，若允许拆箱拦截，实际执行时无法区分，会产生「部分箱被拦、部分箱继续派送」的不一致状态。
- 对比：**发货 / 增值服务 / 销毁** 三种指令类型仍沿用原有的**按箱勾选**模式，本次不做变更。

### 6.2 地址规则

| 指令类型 | 是否需要收件地址 | 说明 |
| --- | --- | --- |
| 发货 | 需要 | 展示完整「收件地址信息」表单 |
| 增值服务 | 不需要 | 仅展示「海外仓备注」 |
| 销毁 | 不需要 | 仅展示「海外仓备注」 |
| **拦截** | **不需要** | **仅展示「海外仓备注」** |

拦截的目标是让货退回海外仓，不存在新的收件地址，因此隐藏整块收件地址表单。

### 6.3 拦截结果回传规则

- 拦截类指令的**指令处理状态由海外仓回传**，取值**只有两种**：`拦截成功`、`拦截失败`。
- 拦截类指令的处理状态**不显示通用的「已完成」** —— 「已完成」是系统对普通指令（放货等）的自动置位，拦截必须体现真实执行结果。
- 若拦截指令已进入处理流程但海外仓尚未回传结果，状态显示 `待海外仓回传`。
- 非拦截类指令（放货等）仍显示 `已完成` + 副行 `处理结果：已处理`。

## 7. 功能需求

### 7.1 发起拦截 —— 创建客户指令

**页面路径**：海外中转单管理 → 创建客户指令
**代码位置**：`src/components/CustomerInstructionCreatePage.tsx`

页面为三步向导：

| 步骤 | 名称 |
| --- | --- |
| 1 | 创建指令 |
| 2 | 按指令选择运单箱子 |
| 3 | 提交完成 |

#### 7.1.1 选择指令类型

四张类型卡片横向平铺，单选：

| 类型 | 说明文案 | 选中后是否展示收件地址 |
| --- | --- | --- |
| 发货 | 需要填写收件地址 | 是 |
| 增值服务 | 无需填写收件地址 | 否 |
| 销毁 | 无需填写收件地址 | 否 |
| **拦截** | **无需填写收件地址** | **否** |

- 默认选中「发货」。
- 选中「拦截」后，页面**隐藏**「收件地址信息」区块（含运单类型、仓库代码、ShipmentID、收件人、州、地址详情、派送方式、邮编、ReferenceID、城市、公司、预约发货时间）。
- 仅保留「海外仓备注」文本域（最大 500 字）。

#### 7.1.2 操作指令配置

以表格形式配置本指令的操作指令，支持「新增指令」追加多行：

| 列 | 说明 |
| --- | --- |
| # | 行号 |
| 指令名称 | 下拉选择，选中后自动带出费用类型、单位、单价、币种 |
| 费用类型 | 只读，由指令名称带出 |
| 单位 | 只读，由指令名称带出 |
| 单价 | 步进器（只读展示） |
| 币种 | 只读，由指令名称带出 |
| 指令要求 | 可编辑文本 |
| 操作 | 删除 |

拦截类型对应的操作指令：

| 字段 | 值 |
| --- | --- |
| 指令名称 | 拦截-退回仓库 |
| 指令编码 | OP-INT-001 |
| 费用类型 | 拦截服务费 |
| 单位 | 票 |
| 单价 | 8.00 |
| 币种 | USD |
| 默认要求 | 对已出库或派送中的货件发起拦截，成功后退回海外仓。 |

> 注意「单位 = **票**」与 6.1 的整票拦截粒度一致 —— 费用按票计，不按箱计。

#### 7.1.3 进入下一步

点击「下一步：选择运单箱子」进入步骤 2。

### 7.2 按指令选择运单箱子（拦截模式）

**代码位置**：`src/components/CustomerInstructionBoxSelection.tsx`

当 `instructionType === '拦截'` 时进入拦截模式，与其它类型渲染不同。

#### 7.2.1 页面头部

| 元素 | 拦截模式 | 非拦截模式 |
| --- | --- | --- |
| 标题 | 全部运单（按运单选择拦截） | 全部客户的指令运单 |
| 右上角徽标 | **已勾选运单：N 票** | 当前可同单箱数：N 箱 |

右上角徽标的交互规则：

- 实时反映当前已勾选的运单数量。
- 未勾选任何运单时：灰色底 + 灰色字（弱化）。
- 勾选 ≥ 1 票：蓝色底 + 蓝色字，数字字号放大一档（强化）。
- 加 `aria-live="polite"`，数量变化时屏幕阅读器播报。

#### 7.2.2 筛选区

- 运单号：模糊匹配，支持回车触发。
- 客户名称：模糊匹配，支持回车触发。
- 搜索 / 重置按钮。
- 下方信息条固定展示：派送费 `50.00 美元/CBM`、指令要求（取用户在步骤 1 填写的值，为空时回退到默认文案）。

#### 7.2.3 运单列表（核心）

每个运单渲染为一张可展开卡片。

**折叠态 —— 表头行**

```
[☑ 选择运单]   ⌄ 运单号   ······   客户单号 · 服务 · 仓库代码 · 国家 · 总箱数 · [已选整票]
└─ 左侧 ────┘                      └────────────── 右侧靠边 ──────────────┘
```

| 位置 | 字段 | 说明 |
| --- | --- | --- |
| 最左 | 选择运单 | **运单级复选框**，勾选即选中整票 |
| 左侧 | 运单号 | 展开 / 收起箭头 + 运单号 |
| 右侧 | 客户单号 | |
| 右侧 | 服务 | |
| 右侧 | 仓库代码 | |
| 右侧 | 国家 | |
| 右侧 | 总箱数 | 该运单下的箱子总数 |
| 右侧末位 | 已选整票 | 勾选后出现的蓝色标记 |

**关键约束**：

1. **所有运单均可勾选**，不因「箱子已全部下过指令」而禁用。
2. **表头不展示「原始箱数」「可下单箱数」** —— 拦截是整票行为，箱数不是决策依据；改为展示运单基础信息。
3. 运单基础信息组通过 `ml-auto` 贴右侧边缘，运单号保持左对齐。

**展开态 —— 运单详情**

| 行 | 字段 |
| --- | --- |
| 1 | 收件人 · 公司 · 地址一 |
| 2 | 城市 · 州 · 邮编 |

- 6 个字段铺满 3 列 × 2 行，无空单元格。
- 字段顺序固定：收件人 → 公司 → 地址一 → 城市 → 州 → 邮编。

**展开态 —— 箱子明细表（只读）**

| 列 | 说明 |
| --- | --- |
| # | 行号 |
| 箱编号 | |
| 指令类型 | 当前指令类型（此处为「拦截」） |
| 已下指令 | 已下过指令显示「已下指令」，否则「—」 |
| 产品中文名 | |
| 重量(KG) | |
| 箱规(CM) | |
| 客户指定是否装箱 | |

> **该表不提供任何复选框** —— 既无行级箱子复选框，也无表头全选复选框。这是 6.1 粒度规则在 UI 上的落地。

#### 7.2.4 底部操作栏

| 元素 | 说明 |
| --- | --- |
| 左侧 | 已选择 N 票运单 |
| 右侧 | 上一步 / 下一步：提交完成 |

- 「下一步：提交完成」在未勾选任何运单时禁用。
- 底部栏吸底（`sticky bottom-0`）。

#### 7.2.5 提交完成

- 展示成功图标 + 「提交完成」。
- 文案：`已确认 N 票运单的拦截指令。`
- 附注：当前为演示数据，本次操作未发送至仓库。

### 7.3 指令列表 —— 拦截结果展示

**代码位置**：`src/components/InstructionListPage.tsx`

#### 7.3.1 状态分组（Tab）

| Tab | 说明 |
| --- | --- |
| 待确认 | 客户已提交，待运营确认 |
| 已确认 | 运营已确认 |
| 已推送海外仓 | 已下发海外仓 |
| 处理中 | 海外仓执行中 |
| 已完成 | 执行完毕（拦截类为回传结果） |
| 驳回 | 被驳回 |
| 取消 | 已取消 |
| 全部 | 全部单据 |

> Tab 上的计数**由数据实时计算**，不写死，保证「显示数字 == 列表实际条数」。

#### 7.3.2 指令处理状态列

**拦截类指令（`指令单类型 = 拦截`）**

| 场景 | 显示 | 颜色 |
| --- | --- | --- |
| 海外仓回传成功 | **拦截成功** | 绿色 |
| 海外仓回传失败 | **拦截失败** | 红色 |
| 已完成但结果未回传 | 待海外仓回传 | 浅灰 |
| 未进入完成态 | 待处理 / 已取消 / 已驳回 | 沿用通用配色 |

- **拦截类指令不显示「已完成」**。
- 拦截结果即主状态，不再额外渲染「处理结果：xxx」副行（避免与主文案重复）。

**非拦截类指令**

- 保持原有行为：主状态 `已完成`，副行 `处理结果：已处理`。

#### 7.3.3 拦截失败整行高亮（关键视觉规则）

> **拦截失败的行，整行使用红色背景。**

| 状态 | 行背景 | 状态文字 |
| --- | --- | --- |
| 拦截失败 | **红色背景**（`rose-50`） | 红色 |
| 拦截失败 + 被勾选 | **加深红色背景**（`rose-100`） | 红色 |
| 拦截成功 | 白色背景 | 绿色 |
| 普通行 | 白色背景 | 默认灰 |

- 高亮覆盖整行所有列，包括左侧冻结（sticky）的复选框列、运单号列、指令单号列。
- 被勾选时红色加深，保证选中态在红底上依然可辨识。
- 设计意图：拦截失败意味着货已派送出去、可能产生实际损失，必须在列表中一眼可见。

| AC-11 | 拦截失败 | 整行红色背景 + 状态文字红色 |
| AC-12 | 拦截失败 + 勾选 | 红色加深，选中态仍可辨识 |
| AC-13 | 拦截成功 | 白色背景 + 状态文字绿色 |
| AC-14 | 非拦截指令 | 保持「已完成」+「处理结果：已处理」 |
| AC-15 | Tab 计数 | 每个 Tab 显示的计数 == 该 Tab 实际渲染行数 |
