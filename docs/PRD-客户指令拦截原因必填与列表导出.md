## 2. 项目背景

拦截流程已上线（见《客户指令 · 拦截流程产品需求文档》），客户可对运单发起「拦截」指令并退回海外仓。但当前拦截指令**只记录了操作指令（如「拦截-退回仓库」）与费用**，没有记录客户发起拦截的**原因**，带来三个问题：

1. **执行缺乏依据** —— 海外仓收到拦截指令后，无法判断拦截的紧迫程度与处理方式（如：客户取消订单需快速退回、地址错误需改址重派、买家退款需走退货流程）。
2. **跟进缺乏上下文** —— 拦截失败意味着货物已派送、可能产生实际损失，运营跟进时只能反复询问客户「当初为什么要拦截」，效率低。
3. **缺乏统计口径** —— 后续要分析「拦截原因分布」（订单取消 / 地址错误 / 买家退款 / 货损等）时，没有结构化数据可统计。

本 PRD 定义「拦截原因」字段的**填写规则、展示规则与导出规则**，作为拦截流程的增量补充。

## 3. 产品目标

1. 客户发起拦截指令时，**必须填写拦截原因**，未填写（或仅填空格）无法提交。
2. 拦截原因在「指令列表」中作为**独立列**展示，运营可一眼看到每票拦截的原因。
3. 拦截原因纳入**列表导出（CSV）**，便于运营线下汇总与统计。
4. 非拦截类型（发货 / 增值服务 / 销毁）**完全不受影响**，不新增字段、不改变交互。

## 4. 产品范围

### 4.1 本期范围

- 「创建客户指令」页：拦截类型下新增「拦截原因」必填文本域。
- 「指令列表」页：新增「拦截原因」列。
- 「指令列表」导出：CSV 表头与数据新增「拦截原因」字段。

### 4.2 不在本期范围

- 拦截原因的**选项化 / 字典化**（预设原因下拉、枚举约束）。
- 拦截原因用于审批流 / 风控判断。
- 拦截原因的回填、编辑与历史版本追溯。
- 拦截原因的多语言、外部系统同步。
- 海外仓侧对拦截原因的展示与处理。

## 5. 用户角色与权限

| 角色 | 核心诉求 | 主要权限 |
| --- | --- | --- |
| 客户 / 客服 | 发起拦截时填写原因 | 创建拦截指令、填写拦截原因 |
| 运营 | 快速查看拦截原因、按原因跟进与统计 | 查看指令列表、导出列表 |
| 海外仓 | 依据拦截原因执行拦截 | 查看回传后的指令信息（本次不涉及） |

## 6. 核心业务规则

### 6.1 字段适用范围

| 指令类型 | 是否需要拦截原因 | 说明 |
| --- | --- | --- |
| 发货 | 否 | 不展示「拦截原因」字段 |
| 增值服务 | 否 | 不展示「拦截原因」字段 |
| 销毁 | 否 | 不展示「拦截原因」字段 |
| **拦截** | **是（必填）** | **展示并强制填写** |

### 6.2 必填规则

- 拦截原因**必填**，提交前校验。
- 仅填**空白字符（空格 / 换行）视为未填写**，校验不通过，提示 `请输入拦截原因`。
- 校验采用浏览器原生表单校验（`required` + 自定义 validity 文案）。

### 6.3 长度规则

- 拦截原因最大 **500 字**，与「海外仓备注」一致，超出长度无法输入。

### 6.4 展示规则

- 「指令列表」中「拦截原因」列**仅对指令单类型 = 拦截** 的票据展示原因内容。
- 非拦截类型票据，该列显示 `-`。
- 拦截原因单元格支持**换行折行展示**（长文本不横向撑破表格）。

### 6.5 导出规则

- CSV 表头在末尾新增「拦截原因」。
- 拦截类型票据导出其拦截原因；非拦截类型票据该字段导出为空字符串。

## 7. 功能需求

### 7.1 创建客户指令 —— 拦截原因必填

**页面路径**：海外中转单管理 → 创建客户指令
**代码位置**：`src/components/CustomerInstructionCreatePage.tsx`

#### 7.1.1 展示位置

当指令类型选择「拦截」时，在「海外仓备注」文本域**上方**新增「拦截原因」字段。

- 该字段与「海外仓备注」同处于「无需收件地址」的内容区块内。
- 因拦截类型无需收件地址，该区块原本仅展示「海外仓备注」，本次在其上方插入「拦截原因」。

#### 7.1.2 字段形态

| 属性 | 值 |
| --- | --- |
| 字段标签 | 拦截原因（带必填标记） |
| 控件类型 | 多行文本框（textarea） |
| 占位文案 | 请输入拦截原因 |
| 必填 | 是 |
| 最大长度 | 500 字 |
| 校验文案 | 请输入拦截原因 |

- 空值或仅空白时，提交被拦截并提示 `请输入拦截原因`。
- 输入有效内容后，自定义校验文案被清除，可正常提交。

#### 7.1.3 交互状态

- 默认选中「发货」时，不展示「拦截原因」。
- 切换为「拦截」时，「拦截原因」出现，且为必填。
- 从「拦截」切回其它类型时，「拦截原因」随区块逻辑隐藏，不参与提交。

### 7.2 指令列表 —— 拦截原因列

**页面路径**：海外中转单管理 → 指令列表
**代码位置**：`src/components/InstructionListPage.tsx`

#### 7.2.1 新增列

在「指令单类型」与「目的地」两列之间，新增「拦截原因」列。

| 属性 | 值 |
| --- | --- |
| 列名 | 拦截原因 |
| 位置 | 「指令单类型」之后、「目的地」之前 |
| 单元格内容 | 拦截类型 → 拦截原因；其它类型 → `-` |
| 单元格样式 | 长文本折行展示（`min-width: 180px`、`max-width: 240px`、保留换行） |

#### 7.2.2 数据模型

- 列表行数据结构新增可选字段 `interceptReason?: string`。
- 拦截类型票据可携带拦截原因，其它类型不带。

### 7.3 指令列表导出 —— 拦截原因字段

**代码位置**：`src/components/InstructionListPage.tsx` 的 `exportRows` 方法

#### 7.3.1 CSV 表头

导出 CSV 的表头在原有 10 列基础上，末尾新增第 11 列「拦截原因」：

```
运单号, 指令单号, 指令名称, 创建时间, 指令处理状态, 处理结果, 客户简称, 仓库代码, 下单类型, 指令单类型, 拦截原因
```

#### 7.3.2 数据映射

- 拦截类型票据：`拦截原因` 字段输出该票据的拦截原因。
- 非拦截类型票据：`拦截原因` 字段输出空字符串。
