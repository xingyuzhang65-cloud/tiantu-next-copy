# 运单天泰发票模板导出需求文档

| 项目 | 内容 |
| --- | --- |
| 版本 | V1.0 |
| 日期 | 2026-11-05 |
| 状态 | 需求评审稿，含当前前端原型说明 |
| 所属模块 | 运单 → 导出 → 天泰发票导出 |
| 关联入口 | 发票、箱单发票、智行发票导出、越南发票导出 |
| 原型页面 | https://xingyuzhang65-cloud.github.io/tiantu-next-copy/v2/ |
| 需求依据 | 用户提供的导出菜单截图，以及新增天泰发票、成功提示、文件命名要求 |

本需求为运单提供天泰发票模板导出入口，并统一发票类导出的成功反馈。导出文件的基础名称为“运单号 发票”，运单号与“发票”之间保留一个半角空格。当前交付为前端原型：菜单与成功提示已完成，尚未生成真实发票文件。真实导出功能按本文件的要求评审、开发及验收。

## 1 需求目标与交付范围

| 需求 | 交付要求 | 当前情况 |
| --- | --- | --- |
| 运单导出菜单 | 按参考截图补齐菜单项 | 已完成前端 |
| 天泰发票入口 | 在“报关资料”之后、“智行发票导出”之前新增“天泰发票导出” | 已完成前端 |
| 成功状态提示 | 点击发票类入口后收起菜单，显示对应的绿色成功提示 | 已完成前端模拟 |
| 文件命名 | 使用系统运单号，按“运单号 发票”命名 | 本 PRD 已明确；真实文件导出时实现 |
| 天泰发票模板 | 使用业务确认的模板版式、字段及文件格式生成发票 | 模板及文件格式待确认 |

本次代码交付不扩展原有运单明细及附件导出的业务逻辑。新增发票入口当前展示的成功消息仅用于验证交互，不能作为真实文件已生成的依据。

## 3 角色与权限

正式功能应复用系统已有的运单数据范围和导出权限，不因提供新模板而扩大数据访问范围。当前原型尚未为该入口接入独立的权限校验。

以下角色划分为评审建议，实际角色名称、授权人员及字段范围需由业务与权限负责人确认。

| 角色 | 运单及导出菜单 | 天泰发票导出按钮 | 文件内字段范围 |
| --- | --- | --- | --- |
| 具备运单导出权限的业务、客服或操作人员 | 在已授权模块及运单范围内可见 | 获得天泰模板导出授权后可用 | 仅输出该角色有权读取的模板字段 |
| 仅具备运单查看权限的人员 | 可查看已授权运单 | 不提供可执行的导出入口 | 无文件输出 |
| 权限管理员 | 按已有管理权限维护授权 | 管理身份不自动代表可以导出所有运单 | 实际导出仍受业务数据范围限制 |

权限需要细化到运单菜单、天泰发票导出按钮、单票数据及文件字段。前后端均应校验；用户手动构造请求时也不能导出越权数据。模板需要的必填字段若无读取权限，阻止导出并给出可理解的原因。

## 4 业务流程与数据范围

### 4.1 当前原型流程

1. 用户在运单列表打开“导出”菜单。
2. 用户点击“天泰发票导出”。
3. 菜单收起，页面顶部居中出现“天泰发票导出成功”的绿色提示。
4. 用户可手动关闭提示，或等待约 4.5 秒后自动消失。

原型当前不校验勾选范围、不请求导出接口、不生成文件。该说明用于界定交付状态，不代表正式功能允许无目标导出。

### 4.2 正式功能流程建议

1. 用户定位并选择目标运单，点击“导出 → 天泰发票导出”。
2. 系统确定导出范围，校验运单、角色权限、模板可用性及必填数据。
3. 校验通过后显示生成中状态，并避免同一次操作被重复提交。
4. 系统读取目标运单的数据快照，套用已确认的天泰发票模板。
5. 按“运单号 发票”的规则命名文件，生成可用的文件内容或下载地址。
6. 浏览器发起文件下载后，页面显示成功提示；失败时给出失败原因及重试入口。

建议优先使用用户勾选的运单作为导出范围。未勾选时是否导出筛选结果，以及是否支持多票批量导出、ZIP 打包和部分成功，均需评审确认。本次不直接沿用现有运单 CSV 的默认范围，以免将原型行为误认为已经确认的发票导出规则。

## 5 文件命名规则

### 5.1 已确认的名称格式

```text
{系统运单号} 发票.{文件扩展名}
```

| 规则项 | 要求 |
| --- | --- |
| 运单号来源 | 系统运单号，对应当前代码中的 `Waybill.id` |
| 分隔符 | 系统运单号后恰好一个半角空格，即 U+0020 |
| 固定后缀 | 中文“发票” |
| 文件扩展名 | 按最终确认的文件类型保留，不属于上述基础名称中的业务文字 |
| 其他文字 | 文件基础名称不额外添加模板名、日期、客户名或“导出”等文字 |
| 运单号处理 | 使用系统保存的规范运单号，保留大小写，不替换为 FBA 号、客户单号或集单号 |
| 缺少运单号 | 阻止生成，提示“运单号缺失，无法导出发票” |

示例运单号为 `HD2606161063` 时，文件基础名称必须为：

```text
HD2606161063 发票
```

若最终确认为 Excel，文件名为 `HD2606161063 发票.xlsx`；若最终确认为 PDF，文件名为 `HD2606161063 发票.pdf`。以上扩展名为条件示例，不代表文件格式已定。

本次涉及的发票文件采用同一命名规则。若后续确认批量导出，每票发票文件仍按此规则命名；ZIP 外层名称、多模板同名处理、浏览器重复下载后自动追加序号等边界应单独明确。浏览器自行追加的重复文件序号不由业务系统主动写入基础名称。

### 5.2 真实下载时的要求

下载响应或前端下载属性应保留中文与半角空格。后缀应与文件实际内容和类型一致，不得仅修改扩展名。运单号如包含文件系统不允许的字符，按系统统一的文件名规范处理；具体字符替换规则需在功能开发前确认。

## 6 模板与字段要求

用户当前提供的是运单菜单截图，尚未提供发票文件样例，因此本 PRD 不将任何发票版式、商品字段、金额算法或公司抬头认定为已确认需求。

| 内容 | 已知要求 | 开发前需补齐 |
| --- | --- | --- |
| 模板标识 | 点击“天泰发票导出”应选择天泰模板 | 模板文件、版本及启用规则 |
| 文件名称 | 按系统运单号生成基础名称 | 无，命名格式已确认 |
| 文件类型 | 保留与实际内容一致的扩展名 | Excel、PDF 或其他格式 |
| 抬头与主体信息 | 使用业务确认的数据来源 | 发货方、收货方、开票主体等字段及来源 |
| 商品明细 | 按模板定义逐项映射 | 字段名称、排序、多行规则和取数口径 |
| 金额与币种 | 使用确认后的口径 | 单价、数量、总价、币种、精度和汇总规则 |
| 缺失信息 | 影响生成的必填项需提示 | 必填项清单、选填项空值展示方式 |
| 页面与工作表 | 遵循批准的模板 | 分页、表头、合计、打印区域及是否可编辑 |

模板字段映射应形成“模板字段 → 系统来源 → 必填性 → 格式 → 示例”的清单。当前 `Waybill` 中虽有收件信息、币种等字段，也不能据此推定它们就是最终发票的数据来源。

## 7 导出状态与提示

### 7.1 成功提示文案

| 入口 | 成功文案 |
| --- | --- |
| 发票 | 发票导出成功 |
| 箱单发票 | 箱单发票导出成功 |
| 天泰发票导出 | 天泰发票导出成功 |
| 智行发票导出 | 智行发票导出成功 |
| 越南发票导出 | 越南发票导出成功 |

成功提示复用系统现有消息样式：页面顶部居中、绿色背景、成功图标，可手动关闭，约 4.5 秒后自动消失。选择菜单项后收起菜单。文案不重复拼接“导出”，例如不显示“天泰发票导出导出成功”。

### 7.2 正式功能状态要求

| 状态 | 触发条件 | 页面反馈 |
| --- | --- | --- |
| 待操作 | 用户尚未发起导出 | 菜单按权限展示 |
| 生成中 | 校验通过并开始生成文件 | 提示“正在生成天泰发票，请稍候”，同次操作防重复提交 |
| 成功 | 文件生成成功且可下载，页面已发起下载 | 显示对应成功文案 |
| 数据不完整 | 缺少必填数据或系统运单号 | 提示具体问题，不显示成功 |
| 无权限 | 权限或数据范围校验失败 | 提示“无权限导出该运单发票” |
| 失败 | 模板不可用、接口异常、生成失败或文件不可下载 | 提示“天泰发票导出失败，请重试”，有业务原因时补充原因 |

正式功能不能仅以点击事件或收到 HTTP 成功状态作为导出成功依据。应检查业务结果及可下载文件；浏览器发起下载不等同于已经确认文件保存到用户磁盘。导出反馈不改变运单的运输状态。

## 8 信息流与运踪流

| 维度 | 本需求处理方式 |
| --- | --- |
| 信息流 | 运单资料与模板数据 → 权限和完整性校验 → 套用天泰模板 → 生成按规则命名的发票文件 → 下载及结果提示 |
| 运踪流 | 发票导出不产生收货、配柜、转运、签收等货物流转节点，不修改既有运踪和运输状态 |

正式导出建议记录操作人、目标运单、模板版本、操作时间及结果，便于追溯。导出记录属于文件操作记录，应与运踪事件分开管理；当前前端原型未实现导出记录持久化。

## 10 评审与待确认事项

| 事项 | 当前结论或待确认内容 |

- `src/components/TableSection.tsx`：导出菜单定义、天泰入口位置及发票类成功反馈调用。
