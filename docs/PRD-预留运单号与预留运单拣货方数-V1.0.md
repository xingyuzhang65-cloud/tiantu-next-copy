## 1. 背景与目标

部分客户在预留仓位前已创建运单，业务人员需要在预留单中关联这些运单，并查看它们后续产生的实际拣货方数。现有备注字段无法明确表达关联关系，也无法据此自动汇总拣货数据。

本需求新增“预留运单号”和“预留运单拣货方数”，实现以下目标：

1. 支持用系统运单号、客户单号、FBA 号关联已有运单，减少人工查找与重复录入。
2. 一张预留单可关联多票运单，同一票运单通过不同编号录入时只计算一次。
3. 自动汇总关联运单的有效拣货方数，拣货新增、更正及撤销后同步更新。
4. 在列表直接查看关联编号及汇总数值，保持人工预留方数不变。

## 3. 页面及字段要求

### 3.1 新增、编辑预留单

“预留运单号”放在表单最下方，位于“备注”之后、保存按钮之前。新增和编辑使用相同的识别及校验规则。

| 配置项 | 规则 |
| --- | --- |
| 字段名称 | 预留运单号 |
| 是否必填 | 选填；不填写时允许按原流程保存 |
| 输入内容 | 系统运单号、客户单号、FBA 号，可混合填写 |
| 多编号分隔 | 英文逗号、中文逗号、空格、换行；兼容制表符及分号 |
| 输入形式 | 单个输入区域内展示多个 Tag，允许继续输入或粘贴 |
| 识别触发 | 粘贴后自动识别；按 Enter 识别；失焦识别；保存前补识别尚未提交的输入 |
| Enter 行为 | 仅识别编号，不直接提交整张表单；中文输入法确认文字时不触发识别 |
| 提示文案 | 支持运单号、客户单号、FBA号；粘贴、回车或失焦自动识别。 |
| 删除入口 | 每个 Tag 右侧的 × |
| 拣货方数输入 | 不提供手工录入入口，由关联运单数据计算 |

识别时去除编号前后的空白，英文字母匹配不区分大小写。分隔产生的空编号忽略。同一编号重复输入或分次粘贴时仅保留一个 Tag。

### 3.2 列表字段位置

列表相关列按以下顺序排列：

```text
拣货方数 → 未拣方数 → 退件方数 → 预留运单号 → 预留运单拣货方数 → 操作
```

其中，原“转货方数”更名为“拣货方数”，原“未转方数”更名为“未拣方数”。有明确运单关联的记录，“拣货方数”为普通匹配与预留运单去重后的有效拣货合计，“预留运单拣货方数”为其中预留来源的子集；“未拣方数”按人工预留方数减总拣货方数、再减退件方数计算。无关联明细的历史记录沿用原有拣货及未拣数值。人工“预留方数”保持不变。

| 字段 | 来源及展示规则 | 是否可直接编辑 |
| --- | --- | --- |
| 预留运单号 | 展示已保存的输入编号，多个编号之间用一个半角空格分隔；保留输入顺序；未填写显示 `—` | 否，通过编辑预留单维护 |
| 预留运单拣货方数 | 汇总有效关联运单的拣货方数；有值显示对应数值，无值显示 `0` | 否 |

展示示例：

```text
预留运单号：HD2606161063 HD2606162231
预留运单拣货方数：7.1
```

运单号内容超出列宽时省略展示，鼠标悬浮可查看完整文本。表格可横向滚动，操作列保持可用。拣货方数单位为立方米（m³），单元格显示纯数值；保留有效小数、不补无意义的末尾零，计算结果最多保留 6 位小数。

## 4. 自动识别与关联交互

### 4.1 Tag 状态

| 场景 | Tag 颜色 | 处理方式 | 保存规则 |
| --- | --- | --- | --- |
| 唯一匹配一票运单 | 蓝色 | 自动确认关联 | 允许保存 |
| 未选择客户 | 黄色 | 提示先选客户，选择后自动重新识别 | 需满足客户必填及关联校验后保存 |
| 一个编号匹配多票且尚未确认 | 黄色 | 展示候选，用户手动勾选 | 未确认前不允许保存 |
| 多票候选已选择至少一票 | 蓝色 | 保留用户所选运单，可继续调整 | 允许保存 |
| 未匹配当前客户的运单 | 红色 | 提示修正编号或移除 Tag | 未处理前不允许保存 |

Tag 悬浮、键盘聚焦或点击时打开关联浮窗。浮窗展示规范的“系统运单号”“客户单号”“FBA号”，缺失的单号信息显示 `—`。

当一个编号命中多票运单时，浮窗按运单列出三类编号并提供复选框，不默认选择第一票，也不默认全选。勾选一票或多票后，保存这些运单的内部 ID。

不额外展示“已合并重复关联”提示或重复的关联卡片。不同输入别名可分别保留为 Tag，关联数量及拣货方数始终按内部运单 ID 去重。

### 4.2 客户切换

识别仅在当前客户范围内进行。切换客户后，保留输入编号并重新识别全部 Tag，不直接沿用上一客户的运单 ID 或候选选择。重新识别失败或仍存在待确认候选时，需处理后才能保存。

### 4.3 保存与编辑

1. 用户选择客户，填写其余原有必填内容。
2. 输入或粘贴一个或多个编号，系统自动识别。
3. 用户处理红色 Tag，并确认黄色 Tag 的候选。
4. 点击保存时，补识别输入框内尚未转换为 Tag 的内容，再进行整体校验。
5. 校验通过后保存输入编号、确认的运单关联和预留单信息。
6. 保存成功后查询关联运单已有拣货数据，更新列表与详情。

编辑入口及可编辑状态沿用预留单现有规则。本需求不扩大现有操作权限。编辑回显已保存编号；候选集合没有变化时保留有效的人工选择，集合变化后要求重新确认。

取消编辑不保存本次关联增删。清空全部 Tag 后允许保存空关联。

### 4.4 移除关联

点击 Tag 右侧 × 移除该输入编号。若还有其他编号指向同一票运单，该运单继续保留并计入一次；只有最后一个有效引用被移除后，才从当前预留单的关联及汇总中移除该运单。

移除不删除运单或拣货记录，不影响其他预留单；编辑场景须保存后生效。

## 5. 拣货方数计算及更新

### 5.1 计算公式

```text
有效关联运单集合 = 对已确认关联的内部运单 ID 去重

每票运单拣货方数 = 该运单所有最新、未撤销的拣货批次方数之和

预留运单拣货方数 = 有效关联运单集合内各运单拣货方数之和
```

计算依据为实际拣货方数，不取人工预留方数或运单预计方数。

### 5.2 去重及版本规则

| 场景 | 规则 |
| --- | --- |
| 同一运单通过系统号、客户号、FBA 号命中 | 只关联、计算一次 |
| 同一运单分多次添加不同编号 | 整张预留单范围内去重 |
| 相同批次、相同版本重复回传 | 不重复累加 |
| 多个不同拣货批次 | 累加各批次最新有效版本 |
| 批次更正 | 使用新版本替换旧版本的值，不把两个版本相加 |
| 批次撤销 | 该批次不再计入合计 |
| 较旧版本晚到 | 忽略旧版本，保留已处理的新版本 |
| 同版本数据冲突 | 标记异常，不覆盖已有成功数据 |
| 关联运单集合变化 | 按保存后的新集合重新计算 |

示例：运单 A 的两个有效批次为 0.8、1.5 方，运单 B 为 4.8 方。关联 A、B 的结果为 `7.1`；即使额外录入 A 的客户单号，仍为 `7.1`。A 的首批更正为 1 方后，结果为 `7.3`；随后 A 的所有批次撤销，结果为 `4.8`。

### 5.3 列表空值及异常规则

| 数据情况 | “预留运单拣货方数”单元格 |
| --- | --- |
| 未填写预留运单号 | `0` |
| 已关联，但尚无拣货回传 | `0` |
| 多票中部分已回传 | 展示已收到的有效数据之和；未回传部分暂计 0 |
| 所有批次已撤销，或有效方数为 0 | `0` |
| 有有效拣货方数 | 展示对应数值，如 `2.3`、`7.1` |
| 同步失败且有历史成功数据 | 保留历史成功数值，详情提示同步异常 |
| 同步失败且无历史成功数据 | 显示 `0`，详情提示同步异常 |

列表该数值列不显示空白、`—`、“待回传”或其他状态文字。显示 `0` 不代表所有关联运单已完成拣货；具体状态从详情查看。

### 5.4 更新时机

保存关联后立即读取已有拣货数据。后续发生拣货新增、分批回传、更正或撤销时，更新所有关联该运单的预留单。列表、详情及导出使用相同的汇总口径；刷新后保留最近有效数据。

同步失败时保留最近成功结果，详情提供异常说明和重试入口；不得用失败返回的空数据覆盖历史成功值。

## 6. 详情、导出与字段设置

### 6.1 详情

预留单操作区的“详细”更名为“明细”。点击后打开居中的大尺寸弹窗，标题为“拣货明细”，使用表格展示当前预留单关联的运单，不再展示原通用详情信息卡片。

表格按以下顺序展示 15 列：运单号、匹配来源、客户单号、客户、渠道、件数、收费重、体积、拣货方数、主品名、当前货站、拣货货站、创建时间、拣货时间、备注。同一内部运单 ID 只展示一行，拣货方数与列表汇总共用数据源。继续使用原“运单号”列，不重复增加“预留运单号”列。

匹配来源显示“普通匹配”或“预留运单”；预留运单使用醒目的橙色标签。普通匹配必须取已有明确的匹配关系，不以同客户、同渠道等条件推测关系。同一运单同时具有两种来源时，显示“预留运单”，只计算一次。

顶部增加“拣货方数：7.1 m³｜其中预留运单拣货：7.1 m³”形式的汇总。前者为全部去重明细的有效方数，后者为其中预留来源的有效方数，分别与主列表“拣货方数”“预留运单拣货方数”核对；无数据为 0。更正、撤销或匹配关系变化后，两处同步重算。

件数为运单件数，收费重、体积取对应运单信息；拣货方数取有效拣货批次合计，缺失为 0。当前货站与拣货货站分别展示，不相互替代。无来源的非数值信息显示 `—`；超长内容省略并支持悬浮完整查看。

弹窗底部右侧显示总条数、每页条数（默认 100，支持 50、20）、上一页/下一页、页码及跳页输入，右下角提供“关闭”，右上角提供 ×。无关联运单时显示“暂无拣货明细”和“共 0 条”。所有预留单状态页使用相同的明细入口。同步失败时保留已有数据，并显示异常说明和重试入口。

MOCK 数据中的收费重、体积、品名及货站为演示元数据；正式环境必须使用对应业务来源。列表或明细中的拣货方数为 0 不代表该运单已拣货完成。

### 6.2 导出与字段设置

导出增加两个同名字段，位置与列表一致。预留运单号使用半角空格分隔；拣货方数沿用列表数值及空值归零规则，不导出“待回传”等状态文字。导出时按最新成功数据计算。

沿用已有导出范围：选中记录时导出选中记录，未选中时导出当前查询结果。字段设置可控制两列显隐，恢复默认时显示两列；隐藏列不删除数据，完整导出仍包含两个字段。

### 6.3 预留运单号查询

筛选区新增“预留运单号”搜索框，提示“单条模糊，多条精确”。支持键盘输入及多行粘贴，逗号、空格、换行可用于分隔编号；点击“查询”或按 Enter 提交，Shift+Enter 可输入换行。

| 输入情况 | 匹配规则 | 示例 |
| --- | --- | --- |
| 空输入 | 不限制预留运单号 | 重置后展示其他条件对应的结果 |
| 一个编号 | 不区分大小写，包含匹配 | `106` 可命中 `HD2606161063` |
| 多个编号 | 对每个完整编号精确匹配，任一命中即可 | `HD2606161063 HD2606161099` 返回关联其中任意一票的预留单 |
| 多个不完整编号 | 不执行模糊扩展 | `HD26061610 HD26061622` 不得命中完整运单号 |

查询覆盖保存的输入编号以及关联运单的系统运单号、客户单号、FBA 号。与客户、预留单号等已有筛选条件取交集，并沿用当前状态页。查询及重置后回到第一页、清空勾选；重置同时清空新搜索框。导出沿用查询后的记录范围。

## 7. 数据及接口约定

| 数据对象 | 必需信息 | 约定 |
| --- | --- | --- |
| 运单识别结果 | 稳定内部 ID、系统运单号、客户单号、FBA 号、所属客户 | 返回当前用户有权访问且属于当前客户的运单及候选 |
| 预留关联 | 预留单 ID、输入编号、确认的内部运单 ID | 预留单 ID + 运单 ID 唯一；输入别名与有效关联分开保存 |
| 拣货批次 | 批次 ID、运单 ID、版本、方数、件数、重量、有效/撤销状态、更新时间 | 方数单位 m³，数值非负；版本递增；按运单 ID + 批次 ID 识别同一批次 |
| 同步结果 | 最近成功时间、最近成功数据、异常信息 | 错误运单数据不得写入当前运单；异常不覆盖成功结果 |

正式服务需提供客户范围内的运单检索、已有拣货数据查询，以及新增、更正、撤销的回传能力；服务端执行客户权限校验和唯一约束。接口地址、鉴权和回传机制由对接设计确定，不将浏览器缓存作为正式业务数据源。

| MOCK-PICK-3345-01 | HD2606163345 | 8 | 1.6 | 已撤销，不计入汇总 |

混合编号测试可使用：

```text
客户：深圳天图电子有限公司 (VIP)

系统运单号：HD2606161063 HD2606162231
客户号 + FBA号：YP2606161063000301 FBA21KK9D12W
同票多编号：HD2606161063 YP2606161063000301 FBA19G6M4C7B
未匹配示例：TEST-NOT-FOUND
```

前两组对应相同的两票运单；第三组对应一票运单，不得重复计算。一个编号命中多票的测试需另行配置同一客户下多个运单共享 FBA 号的测试目录，并验证无默认勾选。

MOCK 必须使用真实存在于演示目录中的运单标识。重复加载不新增重复预留单或批次，不恢复已更正、撤销的数据，也不向用户已有的手工拣货数据追加无关示例批次。

## 10. 当前实现与上线依赖

当前本地原型已提供编号自动识别、列表字段、汇总计算、详情查看、导出及上述 MOCK 场景，运单与拣货数据来自应用内演示目录和浏览器持久化数据源。

本地原型在保存关联、打开详情及详情激活期间同步配置的数据源，并订阅应用内和跨标签页变更；浏览器关闭后不执行后台同步。该能力不等同于已接入真实海外仓回传。

正式上线前需完成：真实运单检索及客户权限校验、关联关系服务端持久化、拣货查询与回传对接、批次版本及撤销约定、更新时效验收。真实接口端点与更新时效目前尚未约定，不在本 PRD 中假定已经交付。

上线验收使用独立测试环境和测试数据；MOCK 示例不作为生产业务数据写入。生产数据缺失时仍遵循列表数值 0、详情说明真实状态的展示规则。
